Implementation-based policy. This page describes the current FutureX Lab website and backend behavior. It is not a claim of legal compliance, certification, or a substitute for review by a qualified legal professional.

1. Scope

This Privacy Policy explains how the FutureX Lab website and its related account, analysis, chat, and news features handle information. It applies to the public site at futurexlab.vercel.app and the FutureX Lab backend used by that site.

Where this page uses a highlighted placeholder, the final value has not been supplied and must be confirmed by the site owner before publication.

2. Information the current site handles

The current implementation handles the following categories of information:

  • Account details: name, email address, a password hash, verification status, and account timestamps.
  • Content submitted to tools: text, URLs, images, or videos submitted for analysis.
  • Chat messages: messages sent to the Lab Guide assistant.
  • Local browser data: the login token, theme choice, reduced-motion choice, and a local list of recent scans.
  • Operational request data: hosting and security providers may process standard request information such as IP address, browser user agent, and timestamps as part of serving and protecting the site.

The current website code does not include third-party analytics scripts and does not set first-party cookies.

3. Accounts and authentication

Creating an account requires a name, email address, and password. Passwords are hashed with bcryptjs; the plain password is not stored in the account database.

Account records are stored in the configured database. When a MongoDB connection is configured, the backend uses MongoDB; otherwise it uses a local database.json file in the backend directory.

Login sessions use a JSON Web Token. The current backend configuration sets a seven-day expiry. The browser stores this token in localStorage under futurex_token and removes it on logout.

4. Tool content and AI processing

When you submit text, a URL, an image, or a video for analysis, the request is sent to the FutureX Lab backend. The backend validates the request and may send content to the configured AI provider, Groq, to generate a result.

The current application code does not write analysis inputs or chat messages into the account database. Requests are processed to produce a response. The AI provider’s own handling of request data is governed by that provider’s terms and privacy policy.

URL analysis includes a server-side fetch of the submitted page. The backend restricts requests to public HTTP/HTTPS addresses and applies a timeout and response-size limit.

5. Local browser storage

The current site stores the following values in your browser:

  • futurex_token: the login token for your account session.
  • fx-theme: your dark or light theme choice.
  • futurex_reduce_motion: your explicit reduced-motion choice.
  • fx_recent_scans: a local list of up to ten recent scan labels, verdicts, scores, and times, which you can clear from the Recent scans area.

These values are stored by your browser and are not first-party cookies. You can remove them by clearing site data in your browser.

6. Email

The backend can send account verification and password-reset emails when an email provider is configured. The current configuration supports Brevo’s API and, as a fallback, SMTP delivery through the configured email service.

Verification tokens currently expire after 24 hours; password-reset tokens currently expire after one hour. Tokens are deleted after successful use or when the account is deleted.

7. Third-party services

The current implementation can involve these third parties:

  • Vercel: hosts the public website.
  • Render: hosts the backend API.
  • MongoDB Atlas: stores account data when a MongoDB connection is configured.
  • Groq: processes AI chat and analysis requests when configured.
  • Brevo or the configured SMTP provider: delivers account emails when configured.
  • Google Fonts: supplies the site’s web fonts.
  • News publishers: the homepage loads article images from sources such as BBC, The Guardian, and The New York Times.

These providers may process technical request data under their own policies. Exact data-processing terms, locations, and retention periods require confirmation from the owner and each provider.

8. Retention

Account records remain until the account is deleted. Verification and password-reset tokens expire as described above and are deleted after use.

9. Security

The current implementation uses password hashing, signed login tokens, HTTPS through the hosting providers, CORS restrictions for approved origins, request-size limits, and rate limiting. These measures reduce risk but do not make any service completely secure.

Do not submit confidential, sensitive, or personal information unless you are authorized to share it and understand how it will be processed.
